# Weekend experiments — 2026-11-28 (Saturday)

The keeper loop (`at loop`, prompt `docs/loops/weekend-keeper.md`) runs these in order, one at a
time, and records every verdict in `docs/run-2026-11-28.md`. Each item below is a spec for one
detached `at` run (or a short mechanical sequence the keeper runs itself).

Rules that apply to every item:

- **One GPU job at a time.** The box queue is the lock; `msft remote status --execute` must show
  `pending 0 running 0` before anything is signalled.
- **Evidence or it did not happen.** Every number in a report comes with the command, the rc and
  the log line that produced it. No estimates are written as measurements.
- **Do not commit or push from an experiment run.** The keeper reviews, gates and commits.
- Scratch files go under `out/` (git-ignored). Only the named deliverables may change tracked
  files, and only the keeper commits them.
- The box is reached without printing its host: `H=$(.venv/bin/python -c "from msft.remote import
  remote_host;print(remote_host().split('@')[-1])")` — never `echo "$H"`, never read
  `configs/worker.local.yaml`.
- Qwen3.5 thinks by default: every request to a served tag sends `think: false` /
  `reasoning_effort: none`.
