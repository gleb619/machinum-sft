## Why 0.8B and not 4B/12B

Both bigger models were started and lost to the network, not to the code:

- **Gemma 4 12B**: stalled at 2.45 GB of ~23 GB, HF never resumed the shard.
- **Qwen3.5 4B**: reached 5.8 GB, HF dropped a completed shard and the cache fell back to
  4.2 GB. Also surfaced a real stack bug — `transformers 4.57.6` cannot load Qwen3.5 —
  fixed in-container to 5.22.2.
- **Qwen3.5 0.8B** was already cached (used for the earlier smoke), so it could finish today.

## Bugs found by running it, and fixed

1. `data` jobs called `msft data` without the `build` action → exit 2 in 0.0 s.
2. The daemon imported `worker.py` at start, so a `git pull` needed a container restart.
3. The entrypoint used `pip`, absent in a uv venv → package never installed. Now uses `uv`.
4. `/opt/llama.cpp` built inside a container disappears when the container is recreated —
   baked into the image and `LLAMA_CPP_DIR` set in compose.
5. `save_pretrained_merged` wrote `tokenizer_class: Qwen3_5Tokenizer` and a list-shaped
   `extra_special_tokens`, which breaks `convert_hf_to_gguf.py`. `merge.py` now normalises
   both and fails if the result does not load.
6. **Training could silently run on CPU.** The generated script now refuses unless
   `MSFT_ALLOW_CPU=1`, prints the device and its VRAM, and the worker prints a GPU line at
   start and reports it in `status`.
7. `no_chatter` missed narrated reasoning ("Thinking Process:", "Analyze the Request") —
   caught by the real output above, added to the pattern list with a test.

## Ollama push: attempted, blocked by namespace

`ollama push machinum-book-ru` uploads the 516 MB layer (reaches 100 %) and then fails with
`not authorized to push to this namespace` — a bare name means the `library/` namespace, which
nobody owns. Everything else is in place, so the last step is one command with the account name:

```bash
docker exec ollama ollama cp machinum-book-ru <your-username>/machinum-book-ru
docker exec ollama ollama push <your-username>/machinum-book-ru
```

Only do that once `msft eval` is green: the current artifact narrates its reasoning and fails
`line_parity`, and a pushed model is public.

## Secret hygiene

The ollama container carries `OLLAMA_API_KEY` in its environment; it appeared in a `printenv`
probe during this session. Rotate it at ollama.com if that output was captured anywhere
durable, and prefer `docker exec` without `printenv` in future runs.
